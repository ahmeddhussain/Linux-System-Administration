5. Ansible, playbook by playbook and role by role

5.1 How Ansible runs in this lab

  • Only on control01, from ~/ahmed-infra/ansible, inside the virtual environment ~/ansible-venv (ansible-core 2.18, boto3). Changes are made on the laptop, committed and pushed; control01 pulls them. Git is the only way code reaches the servers (D-028).
  • It connects as the local ansible account on every host, with the key ~/.ssh/ansible_ed25519 generated on control01, and passwordless sudo. The account is local, not an IPA user, so automation works even when IPA is down, and while IPA is being installed (D-027).
  • ansible.cfg: inventory inventory/aws_ec2.yml; 10 forks; every run logged to ~/ansible.log; any task over 30 minutes fails instead of hanging; the vault password from scripts/vault-password.py; become with sudo; pipelining; SSH keepalives so a dead connection is noticed within a minute.
  • Dynamic inventory (aws_ec2.yml): running instances tagged Project=ahmed-infra, named by their Name tag, reached on their private IP (control01 itself through a local connection). The SSH host key is remembered under the instance ID (HostKeyAlias), so a replaced server at the same IP is recognised as a new machine instead of triggering a false alarm (D-036). Groups: role_* and team_* from the tags, infra, and the groups the FreeIPA collection expects: ipaservers (idm01) and ipaclients (everything else).
  • Pinned collections (requirements.yml): ansible.posix 2.2.2, amazon.aws 12.0.0, freeipa.ansible_freeipa 1.17.0. They are bumped on purpose, in their own commit (D-030).

5.4 The roles

base (every host)

  • Installs troubleshooting packages: vim, tmux, rsync, lsof, tcpdump, bind-utils, ncat, traceroute, SELinux tools, firewalld, chrony.
  • Pins idm01 and util01 in /etc/hosts from the inventory's fixed IPs, so the proxy, NFS and log server stay reachable even if IPA's DNS is down (D-068, DRILL-001).
  • UTC timezone and chrony; SELinux enforcing; firewalld running. It waits for firewall-cmd --state, because systemd reports firewalld "started" before it is ready (INC-003). SSH is allowed in the host firewall.
  • The SSH hardening drop-in /etc/ssh/sshd_config.d/01-ahmed-hardening.conf, mode 0600. It is named 01- on purpose: sshd keeps the first value it reads, and IPA's 04-ipa.conf had been turning keyboard-interactive (PAM password) logins back on (INC-007). Settings:
    • Public keys only: no passwords, no keyboard-interactive, no GSSAPI, no host-based login, no root login, no user environment.
    • X11 forwarding off; on workstations all forwarding is off.
    • MaxAuthTries 4, MaxSessions 10, MaxStartups 10:30:60, LoginGraceTime 30.
    • A silent client is dropped after one unanswered 300 s check; LogLevel VERBOSE; a banner.
    The whole configuration is validated with sshd -t before any restart, so a typo cannot lock everyone out.
  • Banners: /etc/issue.net and /etc/issue carry the company warning, with no OS details; a post-login message.

FreeIPA: idm.yml and five roles

  1. Server (freeipa.ansible_freeipa.ipaserver on idm01, state: present passed explicitly), then ipa_server_verify: every IPA service runs; admin gets a Kerberos ticket and can use the API; DNS answers for ahmed.internal and forwards other names.
  2. Clients, two at a time, control01 last and alone (it runs the playbook). Before each enrollment, ipa_client_prepare:
    • removes an empty /etc/ipa/ca.crt left by a failed attempt;
    • creates a one-time enrollment password on idm01, so the client never sees the admin password;
    • releases the IPA entry of a host that was rebuilt, because IPA refuses a one-time password for a host it still considers enrolled;
    • registers the host with its DNS record.
    Then ipaclient enrolls it, and ipa_client_health checks that SSSD is online and resolves IPA users, restarting an SSSD stuck offline.
  3. ipa_identity on idm01: groups, users (SSH keys, home /users/<name>, expiry), memberships, the company group employees, host groups, HBAC rules, PTR records for every host (rsyslog names log directories by reverse DNS), the automount maps for homes and team shares, sudo commands and rules. Everything comes from identity.yml.
  4. ipa_client_config on every client: labels and creates /users, records a checksum of the identity data, and resets SSSD's cache when it changes. SSSD otherwise keeps an empty sudo-rule cache from before the rules existed.
The state trap
The AWS inventory gives every host a variable state (the instance state, "running"). The FreeIPA roles use a variable of the same name to choose install or uninstall, so both were silently skipped. Passing state: present as a role parameter outranks the inventory variable.

util_storage (util01)

  • Installs LVM and the AWS CLI. It finds the data disks (the unpartitioned NVMe disks) and refuses to continue if their number differs from Terraform's.
  • Adds only blank disks to vg_data: a disk with any filesystem or LVM signature stops the run instead of being overwritten.
  • Creates or grows lv_home, lv_teams and lv_logs (online lvextend --resizefs), makes XFS filesystems and mounts them permanently. Quota accounting (uquota, prjquota) is switched on at mount time, because XFS cannot enable it with a remount.
  • SELinux labels: homes are labelled like /home (equivalence rule), logs as var_log_t, team shares as public_content_rw_t.
  • Installs /usr/local/sbin/ahmed-backup (backup, restore, verify, drill) and a daily timer at 02:00.
  • Restores the latest backup only onto a volume group created in this run, so it never overwrites live data.

log_server (util01)

  • rsyslog with the OpenSSL TLS driver listens on TCP 6514 and accepts only senders presenting a valid IPA certificate.
  • It stores /srv/logs/<sender FQDN>/<program>.log, with the host name taken from the sender's reverse DNS rather than from the message, so one host cannot write into another's directory.
  • Audit records go raw into audit.log, so ausearch -if reads them.
  • Directory and file modes 0750/0640 with group security (laila). The service UMask is overridden to 0027, because rsyslog's default turned 0640 into 0600.
  • 14 days of rotation.
  • The daily audit report: the script ahmed-audit-report plus an hourly timer.
  • The log space guard ahmed-logspace runs every 5 minutes. Above 85% use it deletes the oldest rotated logs until use is under 80%, because rsyslog drops messages it cannot write (DRILL-002).
  • The log port is open in the host firewall to the VPC only.

log_forwarder (every host)

certmonger requests the host's own certificate from the IPA CA (ipa-getcert) and renews it automatically. rsyslog then forwards every message to util01.ahmed.internal:6514 over TLS, checking util01's name. A disk-assisted queue (200 MB, infinite retry) keeps messages while util01 is unreachable.

audit (every host)

Installs auditd and its syslog plugin (audispd-plugins). Every record is tagged with the host name (name_format = HOSTNAME), and audit lines are kept out of the local /var/log/messages. The rules are in /etc/audit/rules.d/50-ahmed.rules, each with a key:

KeyWatches
identitywrites to passwd, group, shadow, gshadow, opasswd

privilegedevery command a real user (UID 1000 and up) runs as root, including inside sudo -i; the ansible account is excluded (its changes are traced in Git and ansible.log)

The role checks that every keyed rule loaded, because augenrules skips a bad line silently (D-063).

nfs_server (util01)

  • NFSv4 over TCP only (v3 and UDP off).
  • Exports /export/home and /export/teams to the two workstation addresses only, sec=sys, root_squash; NFS is open in the host firewall to the workstations only.
  • Creates every IPA user's home from /etc/skel (copying its contents, not /etc/skel/., whose 0755 mode once opened every home), re-owns files by name after a restore, keeps homes private and sets each user's quota.
  • Applies SELinux labels and confirms that NFSv3 is really off and that the exports are active.

team_shares (util01)

Creates /export/teams/<team> mode 2770, so setgid gives new files the team's group and nobody else may enter. A default ACL keeps new files group-writable whatever the creator's umask. company is mode 3770 with group employees: the sticky bit lets only a file's owner delete it. Each share gets an XFS project ID equal to the group's fixed GID (stable across rebuilds) and its quota.

nfs_client (workstations)

Sets the SELinux boolean for homes on NFS, installs autofs, configures it to read automount maps from IPA (ipa-client-automount; the marker is SSSD's automount location), starts it, and confirms it knows both maps. Users' homes appear at /users/<name> and team shares at /teams/<team> on first access.

web_proxy (util01)

Squid has two ports: 3128 "standard" and 3129 "allow-list" (an SELinux port label is added for 3129). It allows only CONNECT to port 443, from the workstations only. The standard port denies the social and streaming lists; the allow-list port allows only its list; there is no caching and no TLS interception. The configuration is validated by Squid before it is used; the access log also goes to syslog; the ports are open to the workstation subnet only.

proxy_client (workstations)

  • dnf uses the proxy (by IP).
  • Every login shell gets https_proxy pointing at its team's port, through /etc/profile.d/ahmed-proxy.sh.
  • Variables can be changed by the user, so the real enforcement is an nftables rule matched on the socket owner's UID: users of allow-list teams are refused on port 3128. Their UIDs are looked up through SSSD, and the run stops if one cannot be resolved, since the rule would otherwise silently miss them.
  • The rule is checked with nft -c and loaded by a boot service. It lives in its own table, so firewalld's tables are never touched.

wireguard_gateway (gw01; tools.yml also on control01)

  • Refuses to run without peers, with placeholder keys, or without the vault key. It derives the public key from the vault private key and refuses a key that does not match the recorded public key, so a wrong vault file cannot silently break every client.
  • Installs wireguard-tools from a repository definition limited to that one EPEL package over HTTPS, and wstunnel 11.1.0 (pinned, SHA-256 verified, root-owned, SELinux bin_t). It loads the kernel module and enables IPv4 forwarding.
  • Writes wg0.conf. WireGuard's own UDP port is closed to the outside; only wstunnel on TCP 443 is open.
  • Per-team firewalld zones (one per team range, by source address) and policies (one per team, allowing exactly the hosts and ports in vpn_team_policy) are written as whole XML files from templates, so a rule removed from the data also disappears from gw01 (D-052). wg0 itself sits in a zone that drops everything else.
  • Runs wstunnel as an unprivileged systemd service, then confirms that every configured peer is in the running tunnel, the zone binding, every policy, and the listener.

compliance (every host; compliance.yml)

Installs openscap-scanner and scap-security-guide and writes a tailoring file from compliance_exceptions. It scans with oscap xccdf eval against the tailored CIS Level 1 profile, reads the score and the pass/fail counts, compresses the HTML report and XCCDF results (about 19 MB uncompressed per host), and brings them to control01. On util01, publish.yml puts them in /srv/logs/reports/openscap/<fqdn>/ with a summary.txt (score against each role's minimum), readable by the security team.

VPN clients use 10.8.0.0/16, split per team: admin 10.8.0.0/24, dev 10.8.1.0/24, ops 10.8.2.0/24. VPN traffic is routed, not NATed (D-024): when sara connects, servers see her own VPN address (10.8.2.x), so firewalls can tell teams apart and logs show who it was. That requires two things: gw01's "source/destination check" is disabled so AWS lets it forward packets, and the private route table sends 10.8.0.0/16 back to gw01.

3.2 Who reaches what

  • Admin: laptop, then the VPN (admin range), then ssh control01-vpn, then any host. If the VPN is broken: ssh control01 through Instance Connect, authenticated by AWS credentials.
  • Employees: laptop, then the VPN (their team's range), then their team's workstation only, which simulates sitting at their own desk. Ops may also reach idm01 and util01 (D-053).
  • Servers accept SSH only from control01, plus the per-team VPN exceptions above.
  • The only port open to the internet is TCP 443 on gw01, which carries WireGuard inside TLS. WireGuard ignores any packet not signed by a known peer key, so the open port reveals nothing.

8. Security operations: audit, compliance, patching, drills

8.1 Audit (D-063)

auditd runs on every host with the keyed rules listed in section 5.4. Two kinds of record matter most:

  • USER_CMD: written by sudo itself for every sudo command, with no rule needed.
  • privileged: every command a real user runs as root, including inside a root shell opened with sudo -i, which sudo alone would not show.

Records leave each host through auditd's syslog plugin and the TLS log path, and land raw in /srv/logs/<fqdn>/audit.log on util01. The security team reads them there with its sudo rights:

sudo ausearch -if /srv/logs/ws-ops01.ahmed.internal/audit.log -k privileged -i     # root commands by real users
sudo ausearch -if /srv/logs/ws-ops01.ahmed.internal/audit.log -m USER_CMD -i --start today
sudo ausearch -if /srv/logs/ws-dev01.ahmed.internal/audit.log -k sshd --start recent
sudo aureport -if /srv/logs/idm01.ahmed.internal/audit.log --summary -i
cat /srv/logs/reports/audit-$(date +%F).txt     # today's summary, refreshed hourly

The rules are deliberately small and explainable rather than the hundreds of vendor STIG rules. They are not locked immutable (-e 2), so Ansible can update them without a reboot; CIS Level 1 does not require it.

8.2 Compliance: CIS Level 1 at 100% (D-064)

Every host is scanned with OpenSCAP against CIS Level 1 (cis_server_l1 for servers, cis_workstation_l1 for workstations), using a tailoring file built from the documented exceptions. The journey:

StageScoreWhat was fixed
Baseline (no fixes)70 to 74120 distinct failed rules
Batch 192 to 93kernel settings, core dumps, kernel modules, unused services masked, cron/at, /dev/shm and /tmp, journald, rsyslog file mode, banner, documented exceptions
Batch 295.6 to 96.2network sysctls, SSH settings (and INC-007)
Batch 397.9 to 98.5PAM through authselect, password policy, sudo defaults
Batch 4100.00crypto policy, AIDE, the last umask and GSSAPI details

Each role's minimum score is now 100 (compliance_min_score); a test fails if any host drops below it, so a regression is caught the same day. Fixes live in our own roles. SSG's generated remediation playbooks were rejected: hundreds of unreviewed changes that would fight our roles on every run.

8.3 Patching cadence (D-065)

CycleWhenCommand
Monthlyfirst Saturday after Red Hat's monthly errata, 02:00 UTCscripts/lab.sh patch
Urgentwithin 7 days of a Critical or Important security advisoryscripts/lab.sh patch --security
New or rebuilt hostsevery up/resumeautomatic (first step of site.yml)

The cycle patches in rings to limit the blast radius of a bad update:

  1. ws-dev01, the canary.
  2. ws-ops01 and util01.
  3. gw01 and idm01.
  4. control01, which reports a needed reboot instead of rebooting itself.

A gate after each ring checks that every host finished and that IPA, SSSD, util01's services and the VPN still answer. A failure ends the cycle, so the later rings stay on the old, working level. Every run writes a record: the dnf history ID, the number of package changes, whether it rebooted, and the kernel, in /var/log/ahmed-patch.log and syslog. Rollback (in docs/runbooks/patching.md): dnf history undo <ID> or dnf downgrade; for a kernel, grubby --set-default the previous one; if all else fails, rebuild the host from code.

8.4 Backups and restore drills (D-056, D-066)

util01's data is backed up daily at 02:00 by a timer, and before every lab.sh down, to the versioned S3 bucket, which keeps old versions for 30 days. On a rebuild the data is restored onto the new volume. The restore drill runs on every up/resume and measures:

MeasureResult (2026-11-03)Target
RPO: data at risk since it was last safe649 s24 h (the daily timer)
Backup duration3 s-
Single-file RTO (a user's deleted file, checked for content, owner and label)1 s5 min
Full-data RTO (98 MB, compared with live)2 s15 min

RPO (Recovery Point Objective) is how much work you could lose; RTO (Recovery Time Objective) is how long recovery takes. Disaster recovery for everything else (identity, configuration) is rebuilding from Git: about an hour (lab.sh up).

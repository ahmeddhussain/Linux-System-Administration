14.3 Glossary

TermMeaning
Break-glassAn emergency access path that does not depend on the normal one (here: Instance Connect when the VPN fails)
CIDRAn address range written as address/prefix, for example 10.0.1.0/24 (256 addresses)
CanaryThe first, least critical host to receive a change
Default denyEverything is blocked unless explicitly allowed
DriftWhen a running system no longer matches its code
EnrollmentJoining a host to FreeIPA
FQDNFully qualified domain name, for example util01.ahmed.internal
HBACHost-based access control: who may log in where (FreeIPA)
IdempotentRunning again changes nothing when the state is already right
KeytabA file holding a host's or service's Kerberos keys
OTPOne-time password; used here to enroll hosts
PTR recordReverse DNS: address to name
RPO / RTORecovery point objective (data you could lose) / recovery time objective (time to recover)
SSHFPDNS records holding SSH host key fingerprints
SSSDThe client daemon for FreeIPA identities, keys, access rules and caching
Split tunnelOnly company traffic (10.0.0.0/16) goes through the VPN
TailoringLocal adjustments to a compliance profile (OpenSCAP)
XCCDF / OVALThe SCAP formats for checklists and results / for how each check is tested

14.4 What is next

The company's admin layer is complete. Remaining build work: app01 (web and database tier at 10.0.3.10, which activates the dev and dba sudo rules) and, optionally, roadmap item 6 (an IPA replica, alerting, golden images, SSH certificates). Everything else is operations, by tickets, using chapter 9. Before the first ticket, run scripts/lab.sh up from nothing: it is the first full build with the hardening, audit and compliance roles, and it should end at 160/160.
